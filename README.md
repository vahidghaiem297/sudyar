# سودیار — وب‌سایت معرفی (فاز ۱)

صفحه‌ی اصلی وب‌سایت عمومی معرفی/فروش سودیار، مطابق ماده پنجم قرارداد (فاز اول: برنامه‌ریزی، معماری و زیرساخت اولیه).

## ساختار پوشه‌ها

```
sudyar/
├── index.html          صفحه‌ی اصلی (ساختار HTML)
├── css/
│   └── style.css       تمام استایل‌ها
├── js/
│   └── main.js         رفتارهای تعاملی (منوی موبایل، اسکرول‌ریویل، هدر)
├── assets/
│   └── icons/          آیکون‌های نهایی PNG (خروجی آماده‌ی استفاده در وب)
├── icon_src/
│   ├── build_icons.py  اسکریپت تولید آیکون‌ها (SVG → PNG)
│   └── *.svg            فایل منبع هر آیکون — برای اصلاح بعدی کافیست این فایل‌ها ویرایش و اسکریپت دوباره اجرا شود
└── README.md
```

## اجرا

چون پروژه فقط از HTML/CSS/JS ساده استفاده می‌کند، نیازی به بیلد یا نصب پکیج نیست. کافیست پوشه را روی یک سرور استاتیک قرار دهید (یا با هر HTTP server ساده باز کنید)، مثلاً:

```
python3 -m http.server 8000
```

سپس آدرس `http://localhost:8000/index.html` را باز کنید.

## آیکون‌ها

۱۱ آیکون به‌صورت بج‌های گرادیانی سه‌بعدی (glossy) و هم‌راستا با پالت رنگی برند طراحی شده‌اند:
- قرمز/رست: بخش «مسئله»
- طلایی: بخش «مزیت رقابتی»
- سبز زمردی: بخش «مشتری هدف»

فایل منبع هرکدام به‌صورت SVG در `icon_src/` موجود است و با اجرای `python3 icon_src/build_icons.py` دوباره در `assets/icons/` به‌صورت PNG (۲۵۶×۲۵۶) بازتولید می‌شوند — یعنی اگر بعداً خواستید رنگ یا شکل یکی از آیکون‌ها را عوض کنید، فقط کافیست SVG مربوطه را ویرایش کنید.

## اقلام باز (نیاز به تکمیل توسط تیم)

- **ویدئوی آموزش (`#tutorial`)**: فایل واقعی ویدئو رو در مسیر `assets/video/tutorial.mp4` قرار بدید (پلیر توی مودال از همین مسیر می‌خونه). اگه ترجیح می‌دید از آپارات/یوتیوب embed کنید به‌جای فایل self-hosted، تگ `<video>` داخل `#videoModal` در `index.html` باید با iframe جایگزین بشه.
- **آیدی پشتیبانی بله**: مقدار فعلی `ble.im/sudyar_support` یک نمونه/جای‌گذاری‌شده است — باید با آیدی واقعی صفحه‌ی پشتیبانی در بله جایگزین بشه (در دو جای `index.html`: متن نمایشی و لینک `href`).
- **محدودیت فاکتور ماهانه‌ی پلن پایه**: روی صفحه «تا ۵۰ فاکتور فروش در ماه» درج شده؛ اگر عدد قطعی کسب‌وکاری متفاوته، در بخش `#pricing` اصلاح بشه.
- **قطع دسترسی بعد از پایان دوره‌ی ۱۵ روزه رایگان**: این بخش، منطق سمت بک‌اند/احراز هویته و در این فاز (وب‌سایت معرفی) فقط به‌صورت بج «۱۵ روز رایگان» روی کارت‌های قیمت‌گذاری منعکس شده؛ پیاده‌سازی واقعی محدودیت ورود باید در فاز مربوط به بک‌اند/پنل انجام بشه.
- **ورود واقعی با گوگل (Google Identity Services)**: کد UI/فرانت‌اند کامل و واقعیه (نه شبیه‌سازی‌شده)، ولی برای فعال شدن نیاز به تنظیمات شماست:
  1. برید به [console.cloud.google.com/apis/credentials](https://console.cloud.google.com/apis/credentials) و یک «OAuth 2.0 Client ID» از نوع Web application بسازید.
  2. توی «Authorized JavaScript origins» آدرس واقعی دامنه‌ی سایت رو اضافه کنید (و برای تست لوکال، آدرس `http://localhost:PORT` رو هم اضافه کنید — گوگل با `file://` یا آی‌پی‌های داخلی مثل `127.0.0.1` معمولاً کار نمی‌کنه، باید حتماً `localhost` باشه).
  3. مقدار `GOOGLE_CLIENT_ID` در ابتدای فایل `js/auth.js` رو با Client ID واقعی خودتون جایگزین کنید.
  4. از نظر هزینه: ورود با گوگل (Sign in with Google) رایگان و بدون محدودیت تعداد دفعاته — برخلاف پنل پیامکی، شارژ یا سقف مصرف نداره.
  **نکته‌ی مهم:** برخلاف بقیه‌ی کتابخونه‌های سایت (که همه به‌صورت آفلاین و از پوشه‌ی خود سایت لود می‌شن)، این یکی مورد استثناست — چون سرویس ورود گوگله، همیشه باید لحظه‌ی ورود به اینترنت وصل باشه و از سرورهای گوگل بارگذاری بشه؛ این محدودیت مخصوص گوگل نیست و برای هر روش ورود با شخص ثالث (اپل، گیت‌هاب و…) هم صادقه، هیچ راه دوری ازش نیست. اگه اینترنت نباشه یا اسکریپت گوگل لود نشه، دکمه به‌طور خودکار مخفی می‌شه و پیام جایگزین «نیاز به اتصال اینترنت» نشون داده می‌شه — به‌جای اینکه یک دکمه‌ی از کار افتاده روی صفحه بمونه.
- **بک‌اند نمونه برای تأیید واقعی توکن گوگل**: توی پوشه‌ی `server/` یک سرور کوچیک Node.js/Express گذاشته شده که دقیقاً کاری که قبلاً فقط توی مرورگر انجام می‌شد (خوندن توکن گوگل) رو سمت سرور و به‌صورت تأییدشده انجام می‌ده، کاربر رو در یک دیتابیس (فعلاً یک فایل JSON ساده برای تست) ذخیره می‌کنه، و یک نشست (session) واقعی با کوکی امن می‌سازه. راهنمای کامل راه‌اندازی توی `server/README.md`. کد فرانت‌اند (`js/auth.js`) از قبل طوری نوشته شده که اگه این سرور روشن باشه ازش استفاده می‌کنه، وگرنه به‌صورت خودکار به حالت قبلی (خوندن توکن فقط توی مرورگر، برای پیش‌نمایش UI) برمی‌گرده — یعنی سایت همیشه کار می‌کنه، چه این سرور رو اجرا کرده باشید چه نه. قبل از استفاده‌ی واقعی (پروداکشن)، حتماً نکات امنیتی نوشته‌شده در `server/README.md` (دیتابیس واقعی، HTTPS، و غیره) رو رعایت کنید.
